# admin/

챗봇 답변을 UI로 관리하는 도구. [Blueprint](https://blueprintjs.com) 기반.

```bash
export AWS_PROFILE=hhr-chatbot
export CONTENT_BUCKET=hhr-chatbot-content
export LEX_BOT_ID=QFUOZQHBTO

aws s3 cp s3://$CONTENT_BUCKET/content/current.json content/current.json   # 최신 받기
yarn admin                                                                 # http://127.0.0.1:5174
```

AWS 없이 화면만 돌려보려면 더미 콘텐츠를 만들면 된다.

```bash
node scripts/seed-content.mjs     # content/current.json 생성 (--force로 덮어쓰기)
```

## 왜 로컬에서 도나요

혼자 쓰는 도구라 **의도적으로 로컬 전용**입니다.

호스팅하면 Cognito(인증) + Admin Lambda + API Gateway + 별도 CloudFront가 필요하고,
관리 화면이 인터넷에 노출되는 것 자체가 새로운 공격면이 됩니다.
로컬 바인딩(`127.0.0.1`)이면 인증이 필요 없고, AWS 리소스도 늘지 않고, 비용도 0입니다.

나중에 호스팅이 필요해지면 `vite.admin.config.ts`의 `adminApi()` 핸들러를
그대로 Lambda로 옮기면 됩니다. 그래서 API 경계를 미리 분리해뒀습니다.

## 화면

```
┌───────────────────────────────────────────────────────────────────────┐
│ 상태 │ 되돌리기 │ 찾기 │ 저장 │ 발행 ▾ │ 로그 │ 테마    ← Navbar      │
├──────────────────┬───────────────────────────┬────────────────────────┤
│ 엔트리 / 미응답   │  엔트리 편집               │  미리보기 / 검증        │
│ 검색·필터·정렬    │  발화 · 블록 (드래그 정렬)  │  (실제 챗봇 컴포넌트)    │
└──────────────────┴───────────────────────────┴────────────────────────┘
        ↕ 드래그로 폭 조절 (새로고침해도 유지)
```

**미리보기는 챗봇이 쓰는 `BlockRenderer`를 그대로 씁니다.** 따로 만들지 않으므로
"어드민에선 멀쩡한데 실제로는 깨지는" 상황이 구조적으로 생기지 않습니다.

## 버튼 4개의 차이

| 버튼 | 하는 일 | 언제 |
|---|---|---|
| **저장** | `content/current.json`에 기록 | 편집 직후 (로컬) |
| **콘텐츠 발행 (즉시)** | S3 업로드 → 챗봇에 반영 | 답변을 고쳤을 때. Lex는 안 건드림 |
| **Lex 발행** | 발화만 담은 zip → import → build | **발화를 고쳤을 때만.** 2~3분 |
| **UI 문구 반영** | 인사말/홈/fallback을 프론트 번들에 주입 | 화면 문구를 고쳤을 때 (프론트 재배포 필요) |

발행 세 가지는 Navbar의 **발행 ▾** 메뉴에 모여 있습니다.

## 검증

편집하는 동안 계속 돌고, **오류가 하나라도 있으면 발행 메뉴가 잠깁니다.**
(저장은 막지 않습니다. 고치다 만 상태를 로컬에 남겨둘 수 있어야 하니까요.)

- 버튼이 **등록되지 않은 발화**를 가리키는 경우 ← 실제로 프로덕션에 있던 버그
  (Lex 퍼지 매칭 덕에 겉보기엔 동작해서 눈치채기 어려웠음)
  → 이제 발화 입력칸 옆에 "어느 인텐트 것인지"가 바로 표시되고, 등록된 발화가 자동완성됩니다
- 발화 중복 (두 인텐트가 같은 발화를 가짐)
- Lex 인텐트 이름 규칙에 안 맞는 id
- 텍스트 블록의 허용되지 않은 태그 / 닫히지 않은 태그
- 잘못된 이미지·링크 URL, 라벨 없는 버튼
- 발화는 있는데 답변이 빈 로케일

오른쪽 **검증** 탭에서 전체 목록을 보고, 클릭하면 해당 항목으로 이동합니다.

## 미응답 질문 인박스

CloudWatch에서 `hit:false` 로그를 모아 빈도순으로 보여줍니다.
= **사람들이 물어봤는데 답을 못 한 질문 목록**.

각 항목의 **+** 를 누르면 어느 인텐트에 넣을지 고르고 바로 발화로 추가됩니다.
그다음 `Lex 발행`을 누르면 끝. 이 루프가 챗봇을 실제 질문에 맞춰 성장시킵니다.

## 단축키

| | |
|---|---|
| `⌘S` | 저장 |
| `⌘Z` / `⇧⌘Z` | 되돌리기 / 다시 실행 |
| `⌘K` | 항목 찾기 (제목·id·발화) |
| `⇧⌘L` | 한국어 ↔ English 전환 |

되돌리기는 **연속된 타이핑을 한 단계로 묶습니다.** 한 글자마다 단계가 쌓이면
`⌘Z`가 쓸모없어지기 때문입니다.

```
  lib/

    entries.ts         ContentFile 변환기 (추가·삭제·정렬·복제)

```

### 블록 id를 심볼로 둔 이유

블록을 React `key`로 식별해야 하는데, 스키마(`Block`)에는 id가 없고
파일에 id를 넣으면 S3의 Source of Truth가 오염됩니다. 그래서 심볼 키를 씁니다.

- `JSON.stringify`는 심볼 키를 무시한다 → 저장 파일이 깨끗하다
- 객체 스프레드는 심볼 키를 복사한다 → 편집해도 같은 블록으로 이어진다
- 깊은 복제(`JSON.parse(JSON.stringify(x))`)는 심볼을 잃는다 → 복제본은 새 id를 받는다

인덱스를 `key`로 쓰면 블록을 지우거나 옮겼을 때 아래 블록의 입력 상태가 엉뚱한 곳에
남습니다. 이전 버전에 있던 버그입니다.
