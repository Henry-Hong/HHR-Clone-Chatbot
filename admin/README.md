# admin/

챗봇 답변을 UI로 관리하는 도구. [Blueprint](https://blueprintjs.com) 기반.

```bash
export AWS_PROFILE=hhr-chatbot
export CONTENT_BUCKET=hhr-chatbot-content
export LEX_BOT_ID=QFUOZQHBTO

aws s3 cp s3://$CONTENT_BUCKET/content/current.json content/current.json   # 최신 받기
yarn admin                                                                 # http://127.0.0.1:5174
```

AWS 없이 화면만 돌려보려면 더미 콘텐츠를 만들면 된다.

```bash
node scripts/seed-content.mjs     # content/current.json 생성 (--force로 덮어쓰기)
```

## 왜 로컬에서 도나요

혼자 쓰는 도구라 **의도적으로 로컬 전용**입니다.

호스팅하면 Cognito(인증) + Admin Lambda + API Gateway + 별도 CloudFront가 필요하고,
관리 화면이 인터넷에 노출되는 것 자체가 새로운 공격면이 됩니다.
로컬 바인딩(`127.0.0.1`)이면 인증이 필요 없고, AWS 리소스도 늘지 않고, 비용도 0입니다.

나중에 호스팅이 필요해지면 `vite.admin.config.ts`의 `adminApi()` 핸들러를
그대로 Lambda로 옮기면 됩니다. 그래서 API 경계를 미리 분리해뒀습니다.

## 화면

```
┌───────────────────────────────────────────────────────────────────────┐
│ 상태 │ 되돌리기 │ 찾기 │ 저장 │ 발행 ▾ │ 로그 │ 테마    ← Navbar      │
├──────────────────┬───────────────────────────┬────────────────────────┤
│ 엔트리 / 미응답   │  엔트리 편집               │  미리보기 / 검증        │
│ 검색·필터·정렬    │  발화 · 블록 (드래그 정렬)  │  (실제 챗봇 컴포넌트)    │
└──────────────────┴───────────────────────────┴────────────────────────┘
        ↕ 드래그로 폭 조절 (새로고침해도 유지)
```

**미리보기는 챗봇이 쓰는 `BlockRenderer`를 그대로 씁니다.** 따로 만들지 않으므로
"어드민에선 멀쩡한데 실제로는 깨지는" 상황이 구조적으로 생기지 않습니다.

## 버튼 4개의 차이

| 버튼 | 하는 일 | 언제 |
|---|---|---|
| **저장** | `content/current.json`에 기록 | 편집 직후 (로컬) |
| **콘텐츠 발행 (즉시)** | S3 업로드 → 챗봇에 반영 | 답변을 고쳤을 때. Lex는 안 건드림 |
| **Lex 발행** | 발화만 담은 zip → import → build | **발화를 고쳤을 때만.** 2~3분 |
| **UI 문구 반영** | 인사말/홈/fallback을 프론트 번들에 주입 | 화면 문구를 고쳤을 때 (프론트 재배포 필요) |

발행 세 가지는 Navbar의 **발행 ▾** 메뉴에 모여 있습니다.

## 답변 본문 서식

텍스트 블록은 HTML 원문을 그대로 보여주고, 그 위에 서식 버튼을 얹었습니다.
contentEditable 기반 에디터를 쓰면 브라우저가 만든 태그가 섞여 들어와 허용 태그를
지킬 수 없고, S3에 저장되는 원문을 눈으로 확인할 수도 없습니다.
버튼은 선택 영역을 태그로 감싸기만 하므로 결과가 항상 예측 가능합니다.

| | | |
|---|---|---|
| 굵게 `⌘B` | 기울임 `⌘I` | 밑줄 `⌘U` |
| 취소선 | 강조 `⌘H` (챗봇 시그니처 하이라이트) | 코드 |
| 문단 | 목록 | 번호 목록 |
| 링크 | 줄바꿈 | |

허용 태그: `<p> <br> <b> <strong> <i> <em> <u> <s> <mark> <code> <ul> <ol> <li> <a>`

> **허용 태그를 바꿀 때는 `src/index.css`의 `.chat-richtext`도 같이 봐야 합니다.**
> Tailwind preflight가 목록·문단·링크 스타일을 전부 리셋하기 때문에, 거기서 되살려두지
> 않으면 "어드민은 허용한다는데 화면에는 아무 차이가 없는" 태그가 생깁니다.
> (실제로 `<ul> <li>`가 그 상태였습니다.)

## 변형 (variations)

텍스트·이미지 블록에는 변형을 여러 개 달 수 있습니다. 답할 때 원본을 포함해
그중 하나를 무작위로 고릅니다. 같은 질문에 매번 똑같은 문장이 나가지 않게 하는 용도입니다.
(Lex의 message variations를 대체한 것으로, 고르는 쪽은 `lambda/index.mjs`의 `resolveBlock`입니다.)

## 답변 블록 네 가지

챗봇이 이해하는 블록은 이게 전부이고, 어드민은 모든 필드를 편집할 수 있습니다.

| 블록 | 필드 | 화면 |
|---|---|---|
| `text` | `html`, `variations` | 말풍선 |
| `image` | `src`, `alt`, `caption`, `variations` | 눌러서 확대되는 이미지 |
| `gallery` | `images[].src`, `images[].alt` | 가로 스크롤 이미지들 (1장이면 `image`와 동일) |
| `actions` | `items[]` — `ask`(발화 전송) / `link`(외부 링크) | 둥근 버튼 묶음 |

## 검증

편집하는 동안 계속 돌고, **오류가 하나라도 있으면 발행 메뉴가 잠깁니다.**
(저장은 막지 않습니다. 고치다 만 상태를 로컬에 남겨둘 수 있어야 하니까요.)

- 버튼이 **등록되지 않은 발화**를 가리키는 경우 ← 실제로 프로덕션에 있던 버그
  (Lex 퍼지 매칭 덕에 겉보기엔 동작해서 눈치채기 어려웠음)
  → 이제 발화 입력칸 옆에 "어느 인텐트 것인지"가 바로 표시되고, 등록된 발화가 자동완성됩니다
- 발화 중복 (두 인텐트가 같은 발화를 가짐)
- Lex 인텐트 이름 규칙에 안 맞는 id
- 텍스트 블록의 허용되지 않은 태그 / 닫히지 않은 태그
- 잘못된 이미지·링크 URL, 라벨 없는 버튼
- 발화는 있는데 답변이 빈 로케일

오른쪽 **검증** 탭에서 전체 목록을 보고, 클릭하면 해당 항목으로 이동합니다.

## 미응답 질문 인박스

CloudWatch에서 `hit:false` 로그를 모아 빈도순으로 보여줍니다.
= **사람들이 물어봤는데 답을 못 한 질문 목록**.

각 항목의 **+** 를 누르면 어느 인텐트에 넣을지 고르고 바로 발화로 추가됩니다.
그다음 `Lex 발행`을 누르면 끝. 이 루프가 챗봇을 실제 질문에 맞춰 성장시킵니다.

## 단축키

| | |
|---|---|
| `⌘S` | 저장 |
| `⌘Z` / `⇧⌘Z` | 되돌리기 / 다시 실행 |
| `⌘K` | 항목 찾기 (제목·id·발화) |
| `⇧⌘L` | 한국어 ↔ English 전환 |
| `⌘B` `⌘I` `⌘U` `⌘H` | 굵게 · 기울임 · 밑줄 · 강조 |

**입력란 안에서도 동작합니다.** Blueprint는 기본적으로 입력란 안의 단축키를 무시하는데,
어드민은 대부분의 시간을 입력란 안에서 보내므로 그러면 아무 데서도 안 먹는 것과 같습니다.

되돌리기는 **연속된 타이핑을 한 단계로 묶습니다.** 한 글자마다 단계가 쌓이면
`⌘Z`가 쓸모없어지기 때문입니다. 되돌리기는 브라우저 기본 실행취소가 아니라
어드민의 편집 이력을 되돌립니다 (블록 삭제·순서 변경까지 포함).

## 테스트

```bash
yarn test        # lambda + 어드민 (82개)
```

발행을 막는 검증 로직은 테스트로 고정해뒀습니다. 특히 **버튼이 등록되지 않은 발화를
보내는 케이스**(실제로 프로덕션에 있던 버그)와 **블록 id가 저장 파일에 새지 않는지**는
회귀하면 바로 드러납니다.

| 파일 | 무엇을 |
|---|---|
| `__tests__/validate.test.ts` | 발행 잠금 조건 — 발화 중복, 등록 안 된 발화, 태그, URL, id 규칙 |
| `__tests__/entries.test.ts` | 정렬·복제·패치, uid가 JSON에 안 나오는지 |
| `__tests__/store.test.ts` | 되돌리기 이력, 타이핑 묶음, dirty |
| `__tests__/html.test.ts` | 허용 태그 / 짝 안 맞는 태그 |

`node --test`가 타입 스트리핑으로 `.ts`를 그대로 돌리므로 테스트 러너를 따로 두지
않았습니다. 대신 **테스트가 닿는 모듈은 상대 import에 `.ts`를 붙입니다.** Node의 ESM
해석기는 확장자를 생략할 수 없기 때문입니다 (`admin/validate.ts`, `admin/lib/entries.ts`).

### 간격

간격은 `--sp-1`~`--sp-6` (4px 배수) 하나만 씁니다. 그때그때 눈대중으로 정하면
6·7·10px이 섞여서 줄마다 미묘하게 어긋납니다. 새 여백이 필요하면 토큰을 쓰거나
`admin.css`에 이름 붙인 클래스를 추가하세요.

**패널 안쪽 여백은 `--sp-2`(8px) 하나로 맞춰져 있습니다.** 탭·검색창·목록·하단
버튼·미리보기 카드가 전부 패널 가장자리에서 8px에 시작합니다. Blueprint 탭 목록은
기본 패딩이 0이라 따로 맞춰줘야 합니다 (`.admin-pane--side .bp6-tab-list`).

값을 바꾼 뒤에는 눈으로만 보지 말고 실제로 재보는 게 빠릅니다. 예를 들어
`margin: 0 auto`가 flex item의 stretch를 꺼서 편집 영역 폭이 항목마다 13px씩
달라지고 있었는데, 스크린샷으로는 알아채기 어려웠습니다.

### 블록 id를 심볼로 둔 이유

블록을 React `key`로 식별해야 하는데, 스키마(`Block`)에는 id가 없고
파일에 id를 넣으면 S3의 Source of Truth가 오염됩니다. 그래서 심볼 키를 씁니다.

- `JSON.stringify`는 심볼 키를 무시한다 → 저장 파일이 깨끗하다
- 객체 스프레드는 심볼 키를 복사한다 → 편집해도 같은 블록으로 이어진다
- 깊은 복제(`JSON.parse(JSON.stringify(x))`)는 심볼을 잃는다 → 복제본은 새 id를 받는다

인덱스를 `key`로 쓰면 블록을 지우거나 옮겼을 때 아래 블록의 입력 상태가 엉뚱한 곳에
남습니다. 이전 버전에 있던 버그입니다.
